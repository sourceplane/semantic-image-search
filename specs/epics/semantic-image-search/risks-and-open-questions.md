# semantic-image-search — risks and open questions

| ID | Risk | State | Notes |
|---|---|---|---|
| SI-A | `baseline-v1` is not yet proven live | OPEN | Proven offline in Baseline CI: the offline bootstrap with the blueprint's own hooks, the lanes' own steps in staged job trees (the migrations applied through a stand-in Supabase Management API over a real Postgres with pgvector and Supabase's roles), and the built Worker served by `wrangler dev` over it, with wrangler's local bucket and namespace. A live bootstrap needs a workspace with Cloudflare (R2 enabled) and Supabase connected and room for two Supabase projects (SI-E) |
| SI-B | The models are verified only against a stand-in | OPEN | The stand-in answers in Workers AI's shapes — JSON mode for the vision call, `{shape, data}` for embeddings — so the calls, the parsing, the vector size, the ranking in pgvector and the pass are real. What Llama 4 Scout writes for the samples, whether it honours the schema every time (an image whose answer does not parse is a failure the next pass retries), and how BGE's similarities sit against the 0.5 bar are not tested. Upstream's 0.28 was OpenAI's; 0.5 is a judgement for BGE, one constant in `lib/db/api.ts` |
| SI-C | The R2 and KV roots, the `r2-data` mint and the `AI` binding under the brokered deploy token have not run together | OPEN | Each is proven in its own starter (blob-starter's R2 root and mint, kv-redis-starter's KV root, rag-chatbot's `AI` binding); this is the first product with all of them. R2 must be enabled on the account once, which no token can do |
| SI-D | `/api/index` is open | ACCEPTED | It describes only the environment's own bucket and nothing it has seen; a call costs one listing. The worst a caller can do is index the owner's new image before the next deploy would (design.md, "Indexing on deploy") |
| SI-E | Two Supabase projects per product | ACCEPTED | Stage and prod are a project each; Supabase's free plan allows two active projects per organization. BOOTSTRAP.md lists it as a prerequisite |
| SI-F | A sample the list names is put back by the next pass | ACCEPTED | So that a deploy always has something to search, the pass seeds what `lib/samples.ts` names; an owner drops the samples by emptying that list (the product's README says how) |
| SI-G | The pass does four images a call, thirty calls a smoke | ACCEPTED | A Worker request's budget bounds a call; an owner who adds more than 120 images at once runs the pass by hand until it answers `"remaining":0` (BOOTSTRAP.md, Troubleshooting) |
| SI-H | Workers AI's cost | ACCEPTED | One vision call and one embedding per new image, one embedding per search not in the cache, billed to the Cloudflare account after its free daily allocation; the twelve samples are well inside it |
